# Правила работы с bb-kimicode-plugin

Это независимый провайдер Kimi Code для BB: TypeScript, публичный Plugin SDK, официальный Kimi Code CLI через ACP. Общение и проектная память — на русском; существующая документация, комментарии и коммиты — на английском.

## Структура и команды

- `server.ts` — настройки, регистрация провайдера и обновление каталога; `host.ts` — мост на хосте исполнения.
- `src/` — credentials, каталог подписки, изолированный config, обработка ошибок ACP и лимитов; `test/` — offline fixtures, регрессии и SDK conformance.
- `scripts/` — установка, упаковка и smoke; `docs/` и `skills/kimicode/` — пользовательская документация.
- Установка: `npm ci --ignore-scripts`. Проверки: `npm run typecheck`, `npm test`, `npm run build`, `npm run check:install`, `npm run check:package`.
- Локальная активация: после сборки проверить отсутствие активных Kimi-тредов (`bb thread count --provider kimi-code --status active`), затем `bb plugin reload kimicode`.
- `npm run smoke` делает настоящий model call. `smoke:usage` читает реальные лимиты без model call. `smoke:errors` и `smoke:background` используют настоящий CLI с loopback fixture API; подробности в `docs/development.md`.

## Ограничения

- Ключи читать только на execution host; не печатать `.env`, ключи, сырые ответы аккаунта. Не менять другие провайдеры и standalone Kimi config.
- SDK и `bb-app` закреплены; обновлять отдельно после проверки совместимости. SDK остаётся production dependency для Git-установок без dev dependencies. `dist/` генерируется и не коммитится.
- Не запускать и не отправлять сообщения в пользовательские треды ради проверки. Проверки CLI выполнять в изолированном home. Ограниченный macOS sandbox может давать `EMFILE` для watchers CLI.
- Обход upstream #4109 временный: условия его пересмотра и критерии проверки записаны в `MEMORY.md`.
- Не делать push, тег или релиз без отдельного поручения пользователя.

## Процесс работы

В начале прочитать `AGENTS.md`, `MEMORY.md`, проверить `git status` и `git log -5`. Сохранять существующие изменения. После завершённого куска обновлять `MEMORY.md`: состояние, следующие шаги, решения с причинами, проблемы и журнал, чтобы другой агент мог продолжить без чата. Секреты в память не записывать.

Когда пользователь явно заканчивает сессию: актуализировать документацию и память, выполнить подходящие быстрые проверки, закоммитить осмысленные изменения без секретов, затем дать готовый промпт для следующей сессии с состоянием, коммитом, задачей и ограничениями. Push не выполнять без просьбы.
